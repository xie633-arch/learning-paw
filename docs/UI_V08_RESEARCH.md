# Learning Paw UI V0.8 研究与方向

更新时间：2026-09-13

## 目标

在不改变 Learning Paw 现有学习逻辑、数据结构和原生 HTML/CSS/JS 技术栈的前提下，优化移动端与桌面端的视觉层级、导航效率和学习沉浸感。

当前阶段不立即重做线上 UI。先维持稳定版本进行数日真实使用，收集实际摩擦点，再集中完成 V0.8。

## GitHub 参考项目

### 1. code-with-antonio/nextjs-duolingo-clone

重点借鉴：

- Desktop Sidebar 与 Mobile Header 分开设计，而不是简单缩放同一布局。
- 导航项有明确 active state。
- 主按钮采用可感知的 pressed / border-bottom 反馈，操作感强。
- Unit → Lesson 的层级清晰，学习路径具有连续感。

不直接照搬：

- 高饱和绿色与卡通化风格。
- 重度游戏化经济系统。
- Next.js / React 技术栈。

### 2. satnaing/shadcn-admin

重点借鉴：

- 桌面侧栏和移动导航分别优化。
- 长文本、导航溢出、滚动区域处理成熟。
- 信息密度高，但通过间距、层级、muted text 控制视觉噪音。
- 模块多时仍能保持清晰导航。

### 3. pedagogist/vanilla-flashcard-app-template

重点借鉴：

- 原生 Web 技术也能做好闪卡与学习进度产品。
- 不需要为了 UI 升级迁移到 React/Vue。
- 与 Learning Paw 目前的轻量、静态 PWA 架构更接近。

## 当前 Learning Paw UI 主要问题

### 1. 首页层级仍偏“Dashboard”，不够“Today First”

目前顶部统计、领域、今日学习、当前领域、训练中心等卡片都拥有接近的视觉权重。

长期使用时真正第一重要的问题应该只有一个：

> 我今天下一步该做什么？

因此 V0.8 首页应进一步突出今日课程 / 今日复习 / 今日 Voice 等下一步动作，而不是先展示大量状态。

### 2. 卡片数量较多，视觉权重过于平均

卡片都使用类似白底、圆角、阴影，容易形成“每一块都重要 = 没有真正重点”的感觉。

需要形成三级视觉层：

1. Primary：今日学习 / 当前最重要任务
2. Secondary：训练、薄弱知识、当前领域
3. Tertiary：数据、来源、设置、历史信息

### 3. 移动端主操作反馈还可以更明确

按钮可以适度借鉴 Duolingo 的 pressed feedback：

- 主按钮增加轻微底部厚度 / active 下沉
- active / completed / locked 状态更容易区分
- 不引入过强颜色

### 4. 课程阅读器已经可用，但缺少“阅读进度感”

V0.8 可加入：

- 顶部细阅读进度条
- 当前课预计时间
- section 进入时的轻量层级提示
- 底部固定主操作保留

### 5. 桌面版没有充分利用宽屏

当前桌面仍较接近“放大的手机单列”。

V0.8 桌面建议：

- 左侧窄导航 Rail / Sidebar
- 中央主学习区
- 右侧可选轻量状态区（仅在宽屏显示）

但不把桌面端做成传统企业后台。

## V0.8 初步方案

### Mobile

1. Today First：今日学习卡成为首页视觉核心。
2. 四领域继续保持 2 × 2 同屏，不再隐藏到横向滑动。
3. 顶部 Header 缩小，占用更少首屏高度。
4. 学习统计压缩为轻量 status strip，而不是单独大型 Hero。
5. Bottom Navigation 保留，但加强 active 状态，降低未选项视觉权重。
6. 主 CTA 使用更明确的 pressed feedback。
7. 课程阅读器增加 reading progress。
8. Review / Test 继续保持单任务沉浸，不显示多余导航。

### Desktop

1. 最大内容宽度从当前约 860px 扩展到约 1100–1200px。
2. 采用窄左侧导航 + 主内容，不做复杂后台。
3. 今日学习与训练中心可以形成主次双栏。
4. Lesson Reader 保持居中阅读宽度，避免正文过宽。

## 领域视觉

不采用高饱和主题色，只给每个领域一个轻量 Accent：

- 手机产品专家：冷灰 / 蓝灰
- 韩语：柔和珊瑚 / 红
- 商圈与零售：绿色
- 行业与商业：琥珀 / 紫灰

Accent 只用于小面积：图标底色、进度、active outline，不用于大面积背景。

## 不能破坏的原则

- 不迁移框架。
- 不重写 StudyEvent / Curriculum / FSRS。
- 不改变现有学习数据。
- 不牺牲 iPhone Safari 性能。
- 不用大量动画。
- 不为了“好看”增加无意义页面。
- 所有 UI 修改必须继续通过 Browser Runtime Smoke Test。

## 实施节奏

### 阶段 A：真实使用 3–7 天

记录：

- 每天最常点的 3 个入口
- 哪些信息基本不看
- 哪些页面需要滚动太久
- 哪些按钮难理解
- 哪些信息希望首屏直接看到

### 阶段 B：V0.8 Mobile First

优先完成：首页层级、顶部 Header、今日任务、底部导航、按钮反馈、阅读进度。

### 阶段 C：Desktop Adaptive

在移动端稳定后再优化 Mac 宽屏布局。

### 阶段 D：实际数据验证

不以“看起来更漂亮”为验收，而以：

- 到今日学习的点击步骤是否减少
- 查找训练 / 路线是否更快
- 首屏是否知道下一步做什么
- 是否减少无意义滚动
- Browser Runtime QA 是否全通过

作为验收标准。
